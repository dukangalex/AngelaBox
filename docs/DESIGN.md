# AngelaBox 设计

2026-09-25 起，按这份设计做。不另起协议栈，不按单个机场改行为。下一包之前先满足这里的判定，再发版。

## 基准

四条都要能被测到，不能只写在介绍里。

| 基准 | 做到的样子 | 做不到的样子 |
|------|------------|--------------|
| 注重隐私 | 配置和日志不上云；崩溃报告默认不含节点和凭证 | 为了排错把订阅或日志传走 |
| 安全防护 | 安装包校验发行证书和 SHA-256；启动失败用中文说明并停住 | 失败后改走 DIRECT，或把内核英文原文丢给用户 |
| 高能低耗 | 用 1.15 自己的 TCP/IP 栈；测速只在需要时跑；熄屏不主动拆隧道 | 每分钟全量测速、双重 urltest、静默丢包让应用空转 |
| 开箱即用 | 节点本身能连，导入后就能代理；同一时刻只有一套分流 | 开关写了但规则不生效；脚本和应用各写一套 |

跟随官方内核，不替换它。AngelaBox 只在运行时覆盖 JSON：不改订阅原文，不改包名 `io.chainbox.app`。Windows 继续暂停。

## 一条流量怎么走

```
订阅原文
  → 导入：只做当前内核认不出的语法（typed DNS、reject、去掉 tun.stack）
  → 分流作者只有一个
       绑了脚本：脚本按 overlay 开关写这一套
       没绑脚本：应用按同一组开关写这一套
  → 绑了链式：在这一套结果上再组 chain
       手机 → 入口（第一跳，本机必须拨得通）→ 落地（出口 IP）→ 目标
  → 失败：停止启动或这条连接失败。不改走 DIRECT
```

链式和脚本可以同时开，顺序固定：脚本先改当前配置的分组和分流，Chain 再把入口接到落地。落地配置上的脚本不套到当前配置。DNS 的 `detour` 保持原来的一跳，不改到 Chain 上。节点服务器域名用直连 DNS 解析，不进 fake-ip，也不绕进 Chain。

出口 IP 必须是落地，不是入口。入口分组不会单独变成出口。

## 和 sing-box 对齐，不和 mihomo 对齐名字

官方没有 `load-balance`，也没有 `fallback`。延迟挑选用 `urltest`，手选用 `selector`。不造同名空组。

`urltest` 官方拨号失败不会换人，会把一个超时节点钉死。链式入口经常是这个组，所以内核在 `v1.15.0-chain.4` 里改成：这次连接最多再试 2 个同组成员，失败的延迟丢掉，拨通的留下。这不是负载均衡。组里每一个都拨不通时，链式仍然没有网，要换一个手机自己连得上的入口。

QUIC：`action: reject`，不要 `method: drop`。复位后应用改走 TCP；静默丢包会让浏览器一直重试。排除国内时，国内域名和 IP 的 UDP 443 先于这条拒绝。

严格路由：默认关。打开只表示没进隧道的包丢掉。Android 的 VPN 接口切换已经由系统回调处理，不要把「打开后可能整机掉线」写成这个开关的定义。

`tun.stack` 在 1.15 废弃，1.17 删除。导入和启动时拿掉，用 sing-tun 自己的栈。这是「高能低耗」对应的内核行为，不是可选主题。

跨协议且两边都是 TLS 的 `detour`（例如 VLESS 再套 Trojan）官方不修（[SagerNet/sing-box#3205](https://github.com/SagerNet/sing-box/issues/3205)）。保存链式时若两边都带 TLS，界面说明这一组合可能没有网，建议其中一跳用 SOCKS、HTTP 或 SSH。应用层绕不过。

## 社区里采纳的，和先不追的

采纳：

- 规则集用 sing-box 的 `.srs`，不把 mihomo 的 `GEOSITE`/`GEOIP` 文件原样塞进来。
- 分流只有一个作者。Clash 用户要的地区组和功能组，用脚本写成真实的 `selector` / `urltest` 和会命中的规则。
- 节点域名的解析走直连引导 DNS。远程 DNS 可以走代理，但只走一跳。
- 1.15 的 TUN 自有栈、按需连接、Android 上需 root 的 `auto_redirect`。`auto_redirect` 默认关。
- 证书校验用整张证书的 SHA-256（官方 1.15.0-alpha.7 起的 `certificate_sha256`）可以留给下一轮内核，不在应用里再做一套。

先不追：

- 不把测试线从已验证的 **1.15.0-alpha.6**（内核 `5ef2960b` / `v1.15.0-chain.4`）直接快进到 **1.15.0-alpha.8**。alpha.7 是 MASQUE 和 HTTP 代理重写，alpha.8 只加了 DNS 服务器地址匹配。官方 1.15.0-alpha.5 在 Android 上有过 TUN 源地址变成局域网地址的报告（[SagerNet/sing-box#4543](https://github.com/SagerNet/sing-box/issues/4543)）。下一次合入官方提交之前，先用同一份双跳配置验证：落地 IP、入口超时换节点、QUIC 复位、DNS 仍是一跳、失败不直连。
- 稳定线仍是 1.14.0 的 1.0.57。1.14.2 只有修复，不为此把测试线拉回去。
- 不为 urltest 做「成本选路」或负载均衡，等官方有字段再接。

## 这几周哪几条基准被打破

| 现象 | 破了哪条 |
|------|----------|
| 开关写着拒绝 QUIC，实际是静默丢弃或根本不写规则 | 开箱即用 |
| 负载均衡、故障转移做成没有行为的 urltest 组 | 开箱即用 |
| 脚本和应用各写一套分流 | 开箱即用 |
| 链式入口钉死在超时的 Cloudflare 443 上，落地没有流量 | 节点能用就能代理；失败要看得见 |
| 发版检查还钉着上一枚内核，包在编译前失败 | 先验证再发 |
| 隧道开着时，把 fake-ip 当成禁止地址，应用内更新失败 | 开箱即用 |

1.0.83 和 1.0.84 分别补了 QUIC 复位，以及 urltest 拨号失败换节点。它们是修补，不是这份设计的替代。

## 下一包之前要先有的验证

不发只改文案的版本。下一版同时满足：

1. 一份普通订阅，不链式，国外站点走代理，国内走直连，出口 IP 是所选节点。
2. 链式：入口是拨得通的节点，出口 IP 是落地；把入口换成一个会超时的节点时，同组里下一个拨得通的节点接上，而不是整机无网。
3. 禁用 QUIC 时 UDP 443 被复位；排除国内时国内 UDP 443 仍直连。
4. 绑脚本时，应用不再写第二套中国直连、广告、QUIC、WebRTC。
5. 故意写坏入口时，启动失败并停住，不改走 DIRECT。
6. 内核仍是经过上述五项的那一枚 commit。合入 alpha.7/alpha.8 之前，这五项再跑一遍。
